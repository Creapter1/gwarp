What this module does
---------------------
- Wraps the current ScriptThread.prototype.executeBlock.
- Tracks elapsed time for active custom call-stack frames with warp=true.
- At a block boundary after about 200 ms, it temporarily turns off warp on
  active custom frames and adds a one-iteration sentinel loop frame. The
  existing interpreter sees warp as disabled and returns at a safe step
  boundary; a microtask then restores the warp flags for the next frame.
- Keeps Turbo mode's current render loop and normal FRAME_MS behavior.
- Does not replace or rewrite ScriptThread.step or app.html.
- Switch-off key, set before the script loads:
    window.GW_DISABLE_CHATGPT_FRAME_BUDGET = true;
- Idempotence key:
    window.__GW_CHATGPT_FRAME_BUDGET_V1__
- dispose() restores the original executeBlock method if no later code wrapped
  this module's wrapper.

Known limitation — important
----------------------------
JavaScript cannot forcibly interrupt a single synchronous block while that
block is still executing. This module can yield after a long warp sequence at
the next executeBlock boundary. A single block/extension operation that
itself blocks for longer than 200–250 ms, or infinite recursion inside one
block handler, needs separate isolation or correction. Do not claim an
absolute 250 ms hard limit without browser stress tests. The existing WARP_MS
still serves as a secondary guard.
