EXECUTIVE SUMMARY
1. The repository contains substantial useful work, but the merge queue overstates readiness in several places. PICK is not equivalent to safe-to-integrate.
2. Highest-risk issue: DeepSeek costume proposals assume CE.state.mode, generic canvas selectors, and data-gw-shape attributes despite ENGINE-MAP documenting CE.state.costumeMode and saying several editor selectors/attributes are UNSURE. Multiple modules attach global document listeners and can intercept unrelated canvas interactions. Do NOT integrate the five costume candidates yet.
3. ChatGPT clone-safety is a meaningful candidate but overrides clone creation/deletion/Stop behavior and has not been browser-tested. It must be diffed against the current engine and tested for side effects before selection.
4. ChatGPT scratch-link is small and has a clear user-consent step, but it depends on a live GW_WEB.load hook and has not been integrated or tested end-to-end. The Gemini extension's hash link therefore also depends on that app handler existing in the published build.
5. DeepSeek protobuf .pmp loader is explicitly incomplete: it treats every non-ZIP buffer as protobuf, relies on a CDN import path/API that is marked UNSURE, returns an empty asset map, and has no real project fixture. Its current test only checks fake byte sequences and error handling; it is not a meaningful compatibility test.
6. Grok has useful broad behavior specifications and 75 written cases, but several edge expectations are explicitly uncertain or potentially contradictory. These are a specification/test backlog, not a passing test suite. G5 extension audit remains open.
7. Gemini's extension has a coherent draft flow, but icon PNG paths referenced by manifests are not present in the current tree (only gspark.svg and make-icons.js are present); packaging requires generating/committing icons. The SVG is documented as a placeholder, and real cross-browser/end-to-end tests are missing. Firefox API namespace compatibility and SPA navigation behavior need explicit testing.
8. ChatGPT UI-AUDIT and Claude's docs/LIVE-UI-VERIFICATION must be reconciled: the latter records 10 PASS results for a narrow scope and explicitly corrects the single-click category finding. Do not claim broader UI/engine correctness.
9. No current repository evidence proves any candidate was integrated into app.html. The current app blob ID should be recorded before future edits and checked afterward.

DEEPSEEK — deepseek/
Files inventoried and statically scanned: costume select/fill/text/eraser/undo A/B/C candidates, speed collision/clone A/B/C candidates, lab/checklists, pmp-loader.js, test-pmp-loader.js, notes, and task list. This is a family-level static review, not execution or line-by-line certification.
Costume candidates — BLOCKED / HIGH RISK:
- ENGINE-MAP documents CE.state.costumeMode, selectedSvg, bitmapTool, svgTool, svgDrag, selectionRect; the candidates commonly inspect CE.state.mode and fields such as fillColor/fontSize/eraserSize that are not confirmed.
- Generic querySelector('canvas') fallback can bind the wrong canvas (stage or another editor), and document-level click/pointer handlers can intercept unrelated UI.
- [data-gw-shape] and [data-gw-selected] are assumed attributes; no source evidence in this review confirms production SVG elements carry them.
- select-C edits a parsed SVG DOM object and writes transform/data attributes, but this review did not find evidence that the modified parsed document is serialized back into the actual costume or rendered editor.
- fill-C's bitmap flood fill must map CSS coordinates to backing-store pixels and be tested for large canvases, transparency, edge pixels, and undo correctness.
- eraser-C changes canvas pixels directly; verify coordinate scaling, pointer capture, context save/restore on cancellation/lost pointer, and that the correct bitmap canvas is targeted.
- text-B attaches a textarea immediately, captures all document clicks, chooses the first canvas, and uses event offsets as SVG coordinates; likely to mis-target stage/other canvases and mishandle zoom/pan. Verify actual mode fields and style input locations.
- undo-C's pushHistory('__undo__'/'__redo__') fallback is not proven to perform undo/redo; a history push is not necessarily an undo command.
Required action: DeepSeek must make a source-evidence map for each API/selector/attribute and revise each candidate into an isolated, opt-in test harness that cannot affect other canvases. Claude should not integrate until these are fixed and the owner authorizes a test branch.
Speed candidates — BLOCKED pending benchmarks:
- LAB-speed reports estimated speed gains; no reproducible benchmark results are established here.
- Collision-B's bounding-box rejection is only safe if bounds cover rotated/scaled sprites and all costume geometries; rotation handling is explicitly uncertain. Prove no false negatives against the existing exact collision function.
- Clone candidates are marked SUPERSEDED in MERGE-QUEUE; do not revive them without a new task and a documented correction.
- Pen optimization was appropriately removed because the private pen hook is not documented.
PMP loader — BLOCKED / INCOMPLETE:
- Non-ZIP is treated as protobuf without a signature check.
- CDN import URL and library export shape are explicitly uncertain.
- assets are returned as an empty Map; projects with costumes/sounds cannot be claimed to load faithfully.
- test-pmp-loader.js uses fake bytes only and has no real .pmp fixture, assertions, or load/save round trip.
Verdict: lab reports identify useful hypotheses, but current candidates are not integration-ready.
