3. FINDINGS — SAFETY (personal data without Dangerous)
=====================================================================
STATIC REVIEW against name + description keywords (auth, location, geo,
weather, clipboard, webrtc, cloud link, account, login, etc.):

- No gallery entry with clear personal-data wording was found OUTSIDE LIST
  for: auth/login, geolocation/IP, clipboard, WebRTC, CloudLink, screen share.
- AI / webhook / Twitch / HTTP-style extensions are correctly treated as
  MODERATE (internet use) when present in MODERATE keys, not Dangerous.
  Examples: pm:MubiLop/penguingpt.js, pm:TheShovel/blockAI.js,
  pm:MubiLop/penguinhook.js, pm:bop_tw/Twitch.js, tw:fetch, tw:godslayerakp/http.
- Face Sensing / Video Sprites / camera: owner rule explicitly excludes camera
  (and mic) from the Dangerous personal-data list for now. They are not in LIST.
  Evidence: RULES string near ~18224 in app.html.

RESULT: No confirmed case of “reads personal data but NOT marked Dangerous”
in the current 184-card table + LIST keys.

UNSURE / residual risk (not failures of the LIST, but gaps to watch):
- Safety depends on exact keyOf(slug). A gallery slug rename without LIST/MODERATE
  update would silently drop a warning. Recommend a small unit test that every
  LIST/MODERATE key exists in gw10GalleryData.
- Extensions loaded only by raw URL (outside gallery) still go through
  GW_EXT_DANGER.match(url); coverage is only as good as norm() + gallery find.
- Full code of each of 184 .js files was NOT re-read this session; LIST claims
  “made by reading each extension’s code” are taken as prior owner/Claude work.
  This audit does not re-prove those code reads.
