FUNCTIONAL / COMPATIBILITY FINDINGS
1. Content-script SPA hooks: content.js overwrites history.pushState and history.replaceState and never restores them. It does not have a top-level per-page idempotency guard, so repeated injection can wrap the wrappers and add duplicate listeners. Add a stable window marker and avoid stacking wrappers/listeners. Prefer a safer SPA navigation strategy if practical.
2. State transitions: the pill checks the current project ID when clicked, which is good. It also removes the pill on non-project pages. Re-test project-to-project navigation, project-to-home navigation, back/forward, and repeated SPA transitions.
3. Storage failures: chrome.storage.sync.get/set callbacks do not surface runtime errors. Add graceful handling for unavailable storage/quota/permission failures so the button does not get stuck in a misleading state.
4. Context menu: background.js matches a project ID from info.linkUrl or tab.url and opens the hard-coded old GitHub Pages URL. Consider validating that a clicked link's hostname is scratch.mit.edu before using its path. Test page-context and link-context behavior separately.
5. Destination URL: background.js, content.js, popup.html and README.txt still point at https://creapter1.github.io/gwarp/. The canonical website URL is not confirmed. Keep the old URL explicitly labelled as previously documented until the owner supplies the exact replacement; do not guess a new host.
6. Hash-handler dependency: the extension opens app.html#scratch=<id>, but README itself says end-to-end load depends on the app's hash handler. The extension alone cannot prove project loading. Test against a build where the handler is present; verify confirm/cancel, invalid IDs, download/network failure, and refresh behavior.
7. Privacy statement: privacy.html says no information is transmitted externally. The extension does open a G-Warp URL containing the Scratch project ID after the user clicks, so make the wording precise: no analytics or independent telemetry, but the selected project ID is included in the destination URL to load that project. The privacy page is not linked from popup.html, making the disclosure difficult to discover.
8. Hide wording: the close control says “Hide G-Warp button permanently,” but popup toggle can re-enable it. Change the label to “Hide button” or “Turn off button” unless “permanently” is explicitly explained as persistent until the setting is changed.
9. Browser scope: manifest permissions appear limited to storage/contextMenus and Scratch host access; content script is restricted to Scratch URLs. This is a good least-privilege starting point. Still verify actual permissions and behaviors in each supported browser and inspect generated packages before release.
