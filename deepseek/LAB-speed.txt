LAB REPORT — SPEED (60 FPS) — DeepSeek (G-Warp native API build)
=================================================================

WHAT CHANGED
------------
Rewritten for G-Warp's real API:
  - Collision wraps GW.spritesTouch(a, b).
  - Clones wrap ScriptThread.prototype.step.
  - Pen removed (G-Warp has no pen API yet).
  - pmp-loader.js now handles ONLY the protobuf kind; ZIP is left
    to G-Warp's built-in loader.

Every UNSURE: below is a name I could not confirm from here. The
modules probe at load time and log one warning if the name is
wrong; they never crash G-Warp.

COLLISION
---------
Version | Speed gain on repeats | Accuracy risk       | Memory | Complexity | Round-2 bugs fixed
--------|-----------------------|---------------------|--------|------------|-------------------
A       | 2-5x                  | Low (same-frame     | Small  | Low        | frame tick, null/identical
        |                       | cache only)         |        |            | guards, unbounded map,
        |                       |                     |        |            | error caching, missing fn
B       | 5-10x when pairs are  | Low (bbox only      | Medium | Medium     | unknown field names, stale
        | far apart             | rejects obvious      |        |            | bbox, rotation (UNSURE),
        |                       | non-overlaps)        |        |            | zero-scale, missing fields
C       | 5-10x + hard cap on   | Medium (returns      | Medium | Medium     | budget default, turbo
        | per-frame work        | false once budget    |        |            | bypass, errors not counted,
        |                       | is spent)            |        |            | warn spam, NaN args

WINNER: B for most projects; C if the project spams collisions
(an easy switch via GW._gwCollisionBudget).

Teach a 14-year-old:
"Two sprites can only touch if their boxes overlap. If the boxes
don't touch, we don't need to do any pixel work at all."

CLONES
------
Version | Speed gain on repeats | Accuracy risk       | Memory | Complexity | Round-2 bugs fixed
--------|-----------------------|---------------------|--------|------------|-------------------
A       | 2-4x                  | Very low (skips     | Small  | Low        | prototype unreachable, double
        |                       | only invisible idle |        |            | wrap, unknown fields, error
        |                       | threads)            |        |            | transparency, empty list
B       | 3-6x                  | Low (skip flag      | Medium | High       | stale flag, broadcast wake,
        |                       | refreshed every     |        |            | snapshot iteration, WeakSet
        |                       | 30 frames)          |        |            | reassign, lazy first refresh
C       | 2-4x                  | Very low (no cross- | Small  | Medium     | cache growth, non-numeric id,
        |                       | frame state)        |        |            | mid-frame broadcast, unknown
        |                       |                     |        |            | fields, double wrap

WINNER: C. It is the only one that never keeps cross-frame state
about a thread, so a broadcast mid-frame always wakes the right
threads. B is faster on paper but its 30-frame window can delay a
woken thread by up to half a second.

Teach a 14-year-old:
"An invisible clone that has nothing to do doesn't need to run
this frame. As soon as it gets a message, it runs again."

----------------------------------------|------------------------------------

Non-ZIP .pmp                            | Converted via pmp-protobuf

UNSURE ITEMS
------------
- UNSURE: G-Warp sprite numeric id field (code probes .id and
  .drawableID, falls back to WeakMap keyed by object).
- UNSURE: G-Warp sprite visibility field (code probes visible,
  isVisible, hidden, _visible; defaults to "visible").
- UNSURE: G-Warp sprite position/size fields for the bbox
  pre-check (code probes x, xpos, left / y, ypos, top / width, w,
  baseWidth, costumeWidth / height, h, baseHeight, costumeHeight /
  size, scale). If none match, B silently falls back to A.
- UNSURE: G-Warp ScriptThread field names for the owning sprite
  (sprite, target, owner) and the stack (stack, blocks, ops). The
  code probes all and defaults to running the thread when a name
  is missing.
- UNSURE: Whether ScriptThread is exposed on window. The clone
  modules fall back to deriving the prototype from the constructor
  of Engine.threads[0] if at least one thread exists.
- UNSURE: Whether G-Warp's collision detection is already bbox-
  based. If it is, version B's bbox pre-check is largely redundant
  but still not harmful.
