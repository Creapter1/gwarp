LAB REPORT — SPEED (60 FPS) — DeepSeek (G-Warp Engine build)
=============================================================

WHAT CHANGED FROM THE PREVIOUS VERSION
--------------------------------------
The previous speed modules were written against a Scratch-style
window.vm / runtime.sequencer layout. G-Warp does NOT have that; it
exposes window.Engine with Engine.sprites, Engine.threads,
Engine.cloneLimit and Engine.isTurbo. This build rewrites all nine
files against window.Engine.

Because I could not open ENGINE-MAP.txt, every place where I did not
know the exact method or property name is marked UNSURE and is
resolved at runtime by probing several likely names. If none match,
the module logs one console warning and does nothing — G-Warp is
never broken.

C       | 5-10x + hard cap    | Medium (budget may    | Medium | Medium     | budget too low, turbo should
        | on per-frame work   | return false once)     |        |            | bypass, error not counted,
        |                     |                        |        |            | warn spam, NaN args

WINNER: B, with C as a safety net when you know the project spams
collisions. B needs the sprite's x/y/size fields; if those names do
not match, B gracefully falls back to A behaviour.

Teach a 14-year-old:
"A sprite can only touch another sprite if their boxes overlap. If
the boxes don't touch, we don't need to look at pixels at all."

NEXT 10 SPEED IDEAS (ranked by gain / effort)
---------------------------------------------
1. Pre-resolve block opcodes to functions, cache in a Map.
2. Store sprite transforms in a Float32Array instead of properties.
3. Lazy GPU texture upload (only when the costume is first drawn).
4. Share silhouette data between clones of the same costume.
5. Batch sprites by shader + texture into few draw calls.
6. OffscreenCanvas for the pen layer in a Worker.
7. A tiny JIT for `forever` loops with pure math.
8. Cache broadcast listeners by message name.
9. Use a Set for "touching" candidate lists.
10. Lower the warp timer from 500 ms to ~200 ms.
