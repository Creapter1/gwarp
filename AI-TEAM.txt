THE MAGIC WORD: "continue"
When the owner just says "continue" (and nothing else), it means:
  1. Re-read AI-TEAM.txt (work log), TODO.txt and your own list on GitHub.
  2. See what you last CLAIMED. If it isn't DONE, keep working on it.
     If it is DONE, CLAIM the next free job and start it.
  3. Reply first with one short line, e.g. "Got it, checking the to-do
     list... continuing with <job>." Then do the work.
  4. Don't ask the owner what to do, the files tell you. Only ask if
     something is truly unclear or would break a rule.

WHEN YOUR LIST IS EMPTY: become a "3-CODE TESTER"
If your own jobs are done (or there's nothing deeper left to research),
don't stop. Pick a topic below, CLAIM it in the WORK LOG, and make
3 DIFFERENT VERSIONS (A, B, C) of the same thing: code, icons or ideas.
Try your best on each one. Claude later runs 3 agents to test them for
real and merges the best, least buggy version into G-Warp.
Files: <your folder>/<topic>-A, -B, -C  +  <your folder>/LAB-<topic>.txt
TOPICS (most important first):
  1. SPEED (MAIN GOAL): every project, no matter how heavy, must run at
     a steady 60 FPS or more. Find what's slow (rendering, clones, pen,
     collision "touching", lists, sounds, big costumes) and write faster
     code for it.
  2. Costumes / paint editor: make it work better and faster.
  3. Music: better songs from the Song maker - more melodies, more bass,
     better drums, sounds teens/adults like (not babyish).
  4. UI ideas, textures, icons (G-Warp's own electric style only).
  5. Education ideas that help kids learn to code in G-Warp.
  6. GWrap AI knowledge (see below).
The owner tests everything with screenshots, slowly, one by one.
If it works and runs properly, that's what matters.

GWRAP AI (the built-in assistant) - knowledge it needs
GWrap AI is an ASSISTANT inside the app, NOT a free-roaming autonomous AI.
It only helps with G-Warp: understanding the user's project, blocks,
sprites, costumes, sounds, extensions, fixing bugs, explaining ideas, and
doing what the user asks inside the app. Nothing beyond that.
Any AI can research and write its knowledge: how to read a project
(project.json), recognise every block and what it does, common bugs and
fixes, game recipes (platformer, shooter, clicker...), and safe answers
for kids. Put it in <your folder>/AI-KNOWLEDGE-<topic>.txt.
Never let it: send data without permission, run JavaScript blocks, act
outside G-Warp, or pretend to be a person.

TEAM RULES (to stop two AIs making the same thing)
1. CLAIM BEFORE YOU START: before working on a job, add a line to the
   WORK LOG:   CLAIMED | <your name> | <job>
   If someone already CLAIMED that job and it isn't DONE, pick another one.
2. When finished, add:  DONE | <your name> | <job> | <files you made>
3. If you find another AI already made the same thing, DON'T redo it.
   Write: REVIEWED | <your name> | <job> | <what could be better>
4. Only ever ADD lines at the bottom of the WORK LOG. Never delete or
   change another AI's lines.
5. Never rewrite app.html or index.html. Never touch another AI's folder.
6. All rules in TODO.txt still apply (same same but different, theirs is
   theirs, safety first, no cats).
7. READ ENGINE-MAP.txt BEFORE WRITING CODE. G-Warp is NOT scratch-vm:
   no window.vm, no runtime.sequencer. Code must use window.Engine and
   the GW_ names in ENGINE-MAP.txt, or say "UNSURE:".
8. NO PLACEHOLDERS: don't hand in empty/placeholder files or tiny stubs
   and call them DONE. If something is missing, log it as PARTIAL, not DONE.
9. GIT COMMIT MESSAGES must start with your name: "Grok: ...",
   "ChatGPT: ...". When saving another AI's work: "Grok (for DeepSeek): ...".
10. WORK LOG lines go at the very BOTTOM, in time order. Use only:
   JOINED, CLAIMED, PROGRESS, PARTIAL, DONE, REVIEWED, UNCLAIMED, NEW ROLE.
11. Don't commit junk files (.claude/, node_modules/, .DS_Store,
   scratch files). Only your folder + the shared .txt files.
12. Every code file needs a matching NOTES-<name>.txt or LAB-<name>.txt
   saying: what it does, where it plugs in, how to test it.
13. FOLLOW STYLE-GUIDE.txt: work goes INTO G-Warp's existing screens -
   never build a separate app/editor with its own name. Use G-Warp's
   dark electric colours.
14. NO OTHER PEOPLE'S CHARACTERS OR BRANDS - not even for testing:
   no Mario/Nintendo, Sonic, Pokemon, Minecraft, Disney, Scratch Cat...
   Use G-Spark or invented characters.
