RULES FOR EVERY AI (these can NOT be broken)
1. SAME SAME BUT DIFFERENT: G-Warp works exactly like Scratch / TurboWarp /
   PenguinMod (same blocks, same results), but keeps ITS OWN LOOK:
   dark theme, electric C-blocks with the electricity animation, black text
   on Events and Control blocks, violet #8b5cf6 / electric green #4ade80,
   G-Spark mascot, Start/Pause/Stop only in the top bar, Music Maker.
   Never change it to look like Scratch. (A Scratch look is only an option
   in More -> Settings -> "Look like Scratch".)
2. THEIRS IS THEIRS, OURS IS OURS: no Scratch art, logos, cat or library
   pictures. Credit every extension creator and follow their licence.
3. SAFETY: extensions that read personal info (IP, location, logins) are
   always marked Dangerous and warned. No accounts. Kids under 13 need a
   parent's OK before any data is sent. Never run JavaScript blocks.
4. No cats anywhere in G-Warp's look.
5. Don't remove or replace features that already exist. Add, don't swap.
6. Projects people send for bug reports stay private and are deleted after.

HOW TO HAND IN CODE PROPOSALS (important, app.html is huge: ~2.3 MB)
- Never rewrite or re-upload the whole app.html.
- Keep the complete candidate in your own AI folder by default, for example chatgpt/.
- Only if explicitly assigned to put a proposal inside app.html/index.html, add a uniquely marked inert block that cannot execute. Do not connect it to any live code path. If safe inert placement is uncertain, do not edit the app file.
    Example candidate files: chatgpt/clone-limit.js (one feature per file)
  and chatgpt/NOTES-clone-limit.txt (purpose, integration point, APIs, risks, tests).
- A candidate may be executable source in its own separate proposal file, but it must remain disconnected from the live app. Do not present an auto-running <script> module as inert code. Include a NOTES file with the real integration point, API assumptions, safety risks, and test steps.
- Only use websites/functions that already exist in app.html. If you are
  not sure a function exists, SAY SO in the NOTES file instead of guessing.
- Mark done items in this file with [x] and your name, e.g.
    [x] (ChatGPT) researched clone limit -> chatgpt/clone-limit.js
- Add new ideas at the bottom under "IDEAS", not in the middle.

Temporary coverage does not authorize live integration; Claude's existing authority/model-verification gates and the owner's approval remain unchanged.
