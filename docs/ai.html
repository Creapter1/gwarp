AI in G-Warp

This page separates what the repository documents as an existing G-Warp assistant from features that are still plans. It is written to help people use the available assistant carefully without assuming that every AI idea has already shipped.

Current documentation status (2 November 2026): GWrap AI has an existing assistant/knowledge-pack design in the project history. Its current live interface and provider connection have not been re-tested for this guide. The downloadable local-model assistant is a development plan, not a feature we can currently promise is available.

1. Know the names

GWrap AI

The in-app helper intended to answer G-Warp questions and help users build scripts. The repository records a knowledge-pack system containing example recipes and tips.

G-Spark

G-Warp's mascot and example sprite. The name does not mean that a local language model is running.

Llama, Gemma and Qwen

Names of model families. A model is the language model itself; it still needs a runtime or service to run it.

Ollama

A separate application that can run supported models on a computer and provide a local model endpoint. Installing Ollama does not automatically connect it to G-Warp.

2. Using GWrap AI

First open the current G-Warp build and look for its GWrap AI or AI helper entry. The exact button location and wording can change; use the current interface rather than relying on an old screenshot.

  1. Open a project and select the sprite you are working on.
  2. Open the GWrap AI helper, if it is present in your build.
  3. Ask for one small, clear result. Say which sprite should act, what should trigger it, and what should happen.
  4. Read the answer. Check that the suggested blocks and values match the current palette before building the script.
  5. Try the script with the Green Flag or the correct event. Observe the Stage, stop the project, and change one thing at a time.
  6. Save a copy after the result works. Do not treat an AI answer as proof that a script has run successfully.

Example prompt

Help me make the selected sprite walk when I press the right-arrow key.
Explain the blocks in order. Use only blocks that exist in this G-Warp build.
Tell me how to test it and what to check if the sprite does not move.

Good questions are specific: “How do I make a score counter?”, “Why does this forever loop never stop?”, or “Explain this script one block at a time.” For a large project, begin with one sprite or one behavior instead of asking for a complete game in a single request.

3. What the knowledge packs do

G-Warp's development history records a JSON knowledge-pack system for GWrap AI. A pack can provide worked recipes and short tips—for example, a movement pattern, a clone pattern, or a common troubleshooting explanation. This is structured reference material that the assistant can look up; it is not the same as retraining the model on the entire app.

A useful recipe should state the goal, required blocks, script order, inputs, expected result, and a small test. If the assistant suggests a block that is missing or behaves differently in your version, do not force the example. Check the actual palette and report the mismatch.

4. Online assistant, API keys and privacy

Privacy reminder: treat an online AI helper as an external service. Do not send passwords, API keys in chat messages, private personal information, private project material, or a child's identifying details.

An earlier source review recorded an Anthropic Messages API connection for the helper: the user question was sent along with a limited summary of selected-project context, such as the selected sprite, variables and some block text. That review also found a key-entry flow with session storage by default and an optional “Remember” choice. Those are historical source-review findings, not a fresh confirmation of the current build or its current model settings.

  • Only enter a provider key into the intended key field in the app, never into a normal chat prompt, screenshot, GitHub file, issue, or log.
  • Before enabling any “Remember” option, understand that it may keep the key in browser storage on that device.
  • Use a temporary or test key when verifying a connection. Remove it when finished.
  • Assume that the prompt and any project context the helper includes may leave your computer for the provider. Do not assume that a context preview or “send no project context” control exists unless the current UI visibly provides it.
  • If the provider rejects the key or model, stop and report the exact error with secrets removed. Do not repeatedly submit a real key.

Verification limit: this documentation pass did not submit an API request or inspect a live running G-Warp browser session. Earlier repository notes flagged a possible model-ID mismatch. Cloud should confirm the current provider, model ID, key-storage behavior, and exact context sent before the guide is upgraded to a fully tested connection tutorial.

5. What about a local Llama or Gemma model?

The AI-team plan dated 26 October describes a future “GWrap AI Local” approach: download a small model once and run it inside the browser using WebGPU. The same plan explicitly says that the local-model feature had not yet been built into the app. It treats Ollama as a possible optional strong mode, not the main design.

That means:

  • A Llama, Gemma or Qwen model downloaded into Ollama is not automatically available inside G-Warp.
  • Ollama and a model are separate from the planned browser-based WebGPU runtime.
  • Do not tell users to look for a Local AI download button or promise offline AI until it exists in the public build and passes a real download, startup, prompt, restart and offline test.
  • Large desktop models and small browser models have different memory and performance requirements. A model that runs in Ollama may be too large for an in-browser version.
For builders: the next implementation work must confirm the model format, licence, download host, WebGPU support, caching, worker isolation, model cancellation, error recovery, context limits and privacy behavior. It must keep the app responsive and offer a clear fallback when WebGPU is unavailable.

6. GWrap AI is not the same as an AI coding agent

The in-app helper is intended to help with G-Warp tasks. It should not be described as a general desktop-control agent, a replacement for Claude Code, or a bridge that lets ChatGPT and Claude talk to one another automatically. Separate tools are needed for repository access, controlled file editing, browser testing and team communication.

7. Quick troubleshooting

  • The AI button is missing: check the app version and current menus. Do not assume an old screenshot matches this build.
  • The assistant cannot connect: check the network, the provider's key and the configured model. Redact the key from any report.
  • The answer names a missing block: compare it with the current palette and ask for a simpler alternative using available blocks.
  • The answer is too broad: ask for one sprite, one event and one short script at a time.
  • The project behaves differently: save a copy, reduce it to a small example, and record expected versus actual behavior.
  • You expected local/offline AI: the local-model plan is not evidence that this feature has shipped. Check the release notes for an implemented and tested version.

8. For contributors and reviewers

Keep public user instructions here in the public main branch. Put internal model research, screenshots waiting to be captured, AI handoffs and implementation notes in the private-workflow area on the ai-team branch. Never put API keys, personal data, or private model files in GitHub.

When documenting a new AI release, record the exact app commit, provider/runtime, model identifier, context fields sent, storage behavior, browser/device, network status and test result. Distinguish SOURCE-VERIFIED, LIVE-TESTED and NOT-TESTED; code being present is not a live connection test.
